# PHP 命令注入审计（php-cmd-audit）

分析 PHP 项目源码，识别系统命令执行相关代码，并追踪用户输入到命令构造点，验证是否存在命令注入风险。

## 适用场景

适合源码存在命令执行函数、进程调用或命令字符串构造，需要判断输入可控性、参数边界和执行影响。

## 不适用场景

只出现 `exec/system/proc_open` 等函数名时，不能直接认定命令注入。必须证明请求输入进入命令关键片段。

## 核心判断

命令注入需要同时确认命令执行点、命令字符串来源、参数是否经过 shell、是否使用白名单或参数数组，以及输入实际可达。

## 证据标准

- Sink 位置、命令字符串构造和用户输入映射。
- 是否存在 shell、参数转义、白名单或固定参数。
- 分支可达性和执行上下文。
- 缺失任一关键 EVID 时标记待验证。

## 决策树

- 找到 Sink：回查命令字符串来源。
- 使用参数数组且不经过 shell：降低风险但继续检查变量。
- 使用完整命令字符串：检查拼接、白名单和执行点。
- 输入经过多层传递：加载 route tracer。
- 证据闭合：输出最小验证与影响。

## 常见误判

- 看到转义函数就认定安全。
- 忽略参数数组和 shell 模式差异。
- 把固定命令中的用户参数当成完整命令控制。
- 无执行回显就确认 RCE。
- 使用破坏性命令验证。

## CRITICAL
- 可优先使用数据流链证据判定可利用性
- 条目可包含：位置证据、Source→Sink 数据流链、可利用前置条件、可执行 PoC 和修复建议

## 分级与编号
- 详见 `shared/SEVERITY_RATING.md`
- 漏洞编号：`{C/H/M/L}-CMD-{序号}`

## 命令执行 Sink（按需）识别以下函数/语法：
- `exec/system/shell_exec/passthru`
- `proc_open/popen/pcntl_exec`
- 反引号语法：`` `cmd` ``
危险模式：
- 命令字符串通过拼接包含用户输入（GET/POST/Body/参数字段）
- 未做白名单/未做 shell 转义，尤其包含 `;|&`、`$()`、反引号、换行等

## 追踪与验证（按需）触发 `php-route-tracer` 的条件：
- 命令字符串由多个变量组成
- 存在参数经过 JSON 解码/多层传递
- 命令构造被 if/try 分支影响

## 报告建议
将证据支持的结论写回项目审计台账或最终报告，不创建空文件。

#### 证据引用（可参考 php-route-tracer）
每条命令注入疑似漏洞有对应 trace 时优先引用 trace 输出中 `## 9) Sink Evidence Type Checklist` 的 **CMD 行**对应证据要点（有 trace 时引用；没有 trace 时直接使用源码位置、参数流和 Sink 证据）：
1. `EVID_CMD_EXEC_POINT`：命令执行函数/语句位置（对应 trace 的 CMD 执行点证据）
2. `EVID_CMD_COMMAND_STRING_CONSTRUCTION`：命令字符串/关键参数构造位置（拼接/模板化证据）
3. `EVID_CMD_USER_PARAM_TO_CMD_FRAGMENT`：用户可控参数到命令关键片段的映射证据

#### tracer 证据缺失处理（可选）
- 若无法定位上述 1~3 任一关键证据要点：该漏洞状态只能标记为 `⚠️待验证`，不得直接给出 `✅已确认可利用`。
