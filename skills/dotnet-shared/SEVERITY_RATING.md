# .NET 代码审计分级标准

## 严重度

使用可达性、影响和利用复杂度三个维度：

```text
Score = R * 0.40 + I * 0.35 + C * 0.25
CVSS  = Score / 3.0 * 10.0
```

| 等级 | Score | CVSS | 含义 |
|---|---:|---:|---|
| Critical | 2.70 - 3.00 | 9.0 - 10.0 | 可直接导致 RCE、认证完全绕过或系统级数据泄露 |
| High | 2.10 - 2.69 | 7.0 - 8.9 | 可造成重大数据、权限或代码执行影响 |
| Medium | 1.20 - 2.09 | 4.0 - 6.9 | 需要条件但可造成实质安全影响 |
| Low | 0.10 - 1.19 | 0.1 - 3.9 | 加固缺陷或有限信息泄露 |
| Info | 0 | 0 | 无可证明安全影响 |

## 三维评分

### 可达性 R

- `3`：无需认证，公开 HTTP 入口或公开服务入口直接可达。
- `2`：需要普通用户认证或有限前置条件。
- `1`：需要管理员、内网、特定角色或复杂资源状态。
- `0`：不可达、死代码或有效防护无法绕过。

### 影响 I

- `3`：RCE、任意文件写入、认证绕过、完整敏感数据泄露。
- `2`：越权、批量数据泄露、关键业务逻辑破坏。
- `1`：有限信息泄露、低影响配置或单用户影响。
- `0`：无实际安全影响。

### 利用复杂度 C

- `3`：单次请求或单步操作即可完成。
- `2`：需要构造参数、多步操作或常见部署条件。
- `1`：需要竞态、特殊配置、链式利用或高权限前置。
- `0`：不可利用或防护有效。

## 状态

- `CONFIRMED`：静态证据链完整且可复核。
- `NEEDS_VALIDATION`：强线索存在，但关键分支、配置或运行时条件未闭合。
- `ENV_DEPENDENT`：依赖 IIS/Kestrel、Windows 身份、MachineKey、权限或部署配置。
- `PATTERN`：只命中危险 API 或模式。
- `NOT_EXPLOITABLE`：有效防护或危险 Sink 实际不可达。

严重度和证据状态必须分开。候选利用链按最弱环节评级。
