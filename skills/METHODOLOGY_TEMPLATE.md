# Skill 方法论模板

该文件是 Skill 编写规范，不是运行中的 Skill，不会被 Skill 列表加载。

```markdown
---
name: skill-name
description: >-
  一句话说明适用问题、主要观察面和预期产出。
metadata:
  tags: [方法论]
---

# Skill 名称

## 适用场景

说明什么目标、信号或问题适合使用本 Skill。

## 不适用场景

说明哪些情况不应套用本 Skill，避免分类先行。

## 核心判断

说明这类问题真正需要判断什么，哪些现象没有实际意义。

## 需要观察的信号

- 入口、参数和权限边界
- 数据流、状态和配置
- 响应差异、错误和可观测证据
- 已有事实、漏洞和重复测试记录

## 候选假设空间

列出候选漏洞类型、成立条件和可能的前置依赖。
候选空间不是漏洞覆盖清单。

## 测试方法

- 基线请求
- 对照请求
- 等价表达和绕过维度
- 最小验证步骤
- 必要时给出可选工具和请求示例

## 证据标准

- 哪些证据可升级为 confirmed
- 哪些只能标记 suspicious 或 conditional
- 哪些结果应判断为 tested_clean、blocked 或 false positive

## 决策树

- 出现什么结果继续深挖
- 出现什么结果切换方向
- 出现什么结果降低结论等级
- 出现什么结果立即停止

## 常见误判

- 扫描器命中
- 版本指纹
- WAF 或网关错误
- 参数名相似
- 响应差异但没有安全影响

## 可选工具与示例

工具、命令和 payload 仅作为候选手段，不是强制执行顺序。
```

编写原则：

- Skill 提供方法论和候选路径，不决定任务范围或完成条件。
- Skill 不得要求 Agent 必须先读取或必须按固定步骤执行。
- 工具示例放在方法末尾，避免先入为主。
- 未命中 Skill 分类不代表目标安全，命中分类也不代表漏洞成立。
