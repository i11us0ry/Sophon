# PHP 审计统一输出标准

本文件用于补齐上游引用但未提供的统一证据和输出标准。

## 状态

- `CONFIRMED`：入口、参数、分支和 Sink 证据链闭合。
- `NEEDS_VALIDATION`：存在可利用线索，但仍缺少关键证据。
- `ENV_DEPENDENT`：依赖特定运行时、Web 服务器、PHP 扩展或部署配置。
- `NOT_EXPLOITABLE`：有效防护存在，或 Sink 实际不可执行。
- `PATTERN`：仅发现危险模式。

## 证据置信度

| 等级 | 条件 |
|---|---|
| `HIGH` | 入口、Source、参数变换、分支、Sink 和防护检查都有 file:line 证据 |
| `MEDIUM` | 数据流基本成立，但缺少一个关键分支、部署条件或框架行为证据 |
| `LOW` | 只有 Sink 或模式命中，无法证明可达和参数可控 |

置信度与严重度分开计算。`LOW` 不得写成 `CONFIRMED`。

## 漏洞条目必填字段

- 漏洞编号。
- 类型代码。
- 严重等级和 CVSS。
- 状态和证据置信度。
- 路由或合成入口 ID。
- 文件和行号。
- Source 到 Sink 数据流。
- 分支与防护证据。
- `EVID_*` 引用。
- 前置条件。
- 静态验证模板。
- 修复建议。
- 未验证项。

## 覆盖与漏报

- 覆盖矩阵每行必须填写已执行、不适用或已延期及依据。
- `PARTIAL`、`UNRESOLVED`、`PATTERN` 和 `LOW` 项不得静默删除。
- 缺失证据必须进入“Trace 未闭合 / 待补证风险池”。
- 上游缺失的 SSRF、XSS、CSRF 专项能力必须明确标记为已延期。
