# Java 代码审计编排参考

本技能是方法论，不是固定作业流水线。入口仍是 `java-code-audit`；主 Agent 根据项目事实、证据缺口和当前收益决定阶段与并行方式。

## 适用场景

适合中大型 Java Web 项目需要组织路由、鉴权、依赖、调用链、专项漏洞和利用链分析时使用。

## 不适用场景

如果只需查看单个类、确认单个依赖或验证一个已知入口，不必加载完整编排流程。

## 核心判断

先定位真实入口和 Sink，再决定是否追踪调用链或加载专项技能。阶段、Worker 数量、覆盖矩阵和中间产物都不能替代漏洞证据。

## 决策树

- 项目结构未知：先建立模块、源码目录、构建文件和 artifact 索引。
- 路由未知：进入路由与鉴权分析。
- 组件命中：检查实际加载、使用位置和公开入口。
- Sink 明确但参数流不闭合：进入调用链追踪。
- 证据闭合：进入专项复核和漏洞报告。
- 当前路径收益不足：切换入口、artifact、Sink 类型或分析层次。

## 常见误判

- 把组件版本命中直接当成可利用漏洞。
- 把无鉴权入口直接当成存在敏感副作用。
- 只看关键字，不追踪分支和数据流。
- 把反编译字符串当成运行时行为。
- 为了完成阶段而生成没有证据支持的结论。

## 证据标准

- 结论必须绑定文件、符号、行号、参数流、分支和 Sink。
- 组件版本、模式字符串和无鉴权入口只能作为候选。
- 只有入口可达、参数可控、校验缺口和敏感效果闭合时才能标记 `CONFIRMED`。
- 缺少部署条件、运行时分支或配置证据时标记 `NEEDS_VALIDATION` 或 `ENV_DEPENDENT`。

## 材料发现

- 从当前项目工作区、会话附件、项目事实和已解包目录自动定位源码、JAR、WAR、CLASS 和构建文件。
- 不要求用户重复提供 `source_path`、`output_path`、源码根目录或输出目录。
- 不要求创建固定目录树。路由、鉴权、候选风险和证据写回项目审计台账；漏洞使用 `project_report_finding`。

## 按需阶段

### 1. 项目建模

- 识别框架、模块、构建方式、源码目录、二进制目录、配置和入口。
- 建立模块与 artifact 索引，优先读取 `.java`；没有源码时再反编译目标类或读取元数据。
- 不要求全量反编译，不按目录盲目生成巨大中间产物。

### 2. 路由与鉴权

- 提取 HTTP 路由、Servlet、Filter、Interceptor、CLI、任务和消息入口。
- 对每个入口记录 handler、参数来源、请求方法和鉴权链。
- 鉴权判断要区分“无鉴权”“登录校验”“能力/角色校验”“对象归属校验”。
- 没有路由或无法证明可达的 Sink 保存为候选，不直接升级漏洞。

### 3. 依赖与危险 Sink

- 优先从 `pom.xml`、Gradle、`META-INF/MANIFEST.MF`、`META-INF/maven/**/pom.properties` 和 artifact 文件名提取组件版本。
- 扫描命令执行、反序列化、SQL、XML、文件操作、SSRF、表达式、模板和 JNDI 等 Sink。
- 组件版本命中只代表候选；必须结合加载情况、配置、入口和使用位置判断影响。

### 4. 数据流追踪

按证据收益选择入口，追踪：

```text
入口 -> 参数读取 -> 分支/校验 -> 变量变化 -> 危险 Sink -> 影响
```

只有入口、可控性、分支和 Sink 证据闭合时才标记 `CONFIRMED`。缺失条件时标记 `NEEDS_VALIDATION` 或 `ENV_DEPENDENT`。

### 5. 专项审计

仅加载与当前 Sink 匹配的技能，例如：

- SQL：`java-sql-audit`
- XXE：`java-xxe-audit`
- 文件上传：`java-file-upload-audit`
- 文件读取：`java-file-read-audit`
- 反序列化：`java-deserialization-audit`
- SSRF：`java-ssrf-audit`
- 表达式注入：`java-expression-inject-audit`
- 鉴权：`java-auth-audit`
- 路由：`java-route-mapper`
- 调用链：`java-route-tracer`

没有对应 Sink 时不为了填满流程启动专项技能。

### 6. 利用链与报告

- 只消费已有证据，不给链路补造新证据。
- 利用链按最弱环节确定状态。
- 报告通过项目事实、审计单元和漏洞记录生成，不强制固定文件名。
- 未闭合项写入待补证风险池，不能静默丢弃。

## 并行策略

- Worker 是可选手段，不是前置条件。
- 并发上限以 Sophon 当前配置为准；不能并行时按证据优先级串行。

## 无进展处理

连续分析没有新增事实、审计单元、测试结果或漏洞时：

1. 停止重复读取相同文件。
2. 写出已确认、已排除或待验证结论。
3. 切换入口、artifact、证据类型或分析路径。
